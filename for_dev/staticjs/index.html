📘 Gradus Static.JS — Полная документация (июнь 2026, v2.5.1)

Gradus Static.JS — это микро‑фреймворк для создания динамических сайтов на статических хостингах (GitHub Pages, Netlify, обычный сервер без PHP/Python).
Он позволяет вставлять в HTML специальные метки {функция:аргументы}, которые при загрузке страницы заменяются на реальные данные: из кэша, локальной базы, API, генераторов и т.д.

Главная особенность: вам не нужно писать серверный код — всё работает прямо в браузере. Вы просто пишете обычный HTML и добавляете плейсхолдеры. Фреймворк запускается автоматически, даже если файл site.js полностью пуст.

🔄 Что нового в июне 2026 (v2.5.1) — Shop Update и усиление надёжности:
  • Автоинициализация: фреймворк сам запускается при загрузке страницы. Вам больше не нужно писать window.addEventListener('load', ...) в site.js — достаточно подключить скрипты.
  • Пустой site.js: фреймворк корректно работает, даже если файл site.js пустой или отсутствует. Все встроенные плейсхолдеры будут функционировать.
  • Устойчивость к ошибкам: ошибки в пользовательских обработчиках не роняют фреймворк, а выводят ERROR. Отсутствие db.json больше не вызывает сбоя.
  • Shop Update: новый модуль GradusWeb.shop (см. документацию Gradus Web) и плейсхолдеры для магазина: product_name, product_price, product_desc, cart_count, cart_total.
  • Новые плейсхолдеры: qr_code (QR-код), spell_check (проверка орфографии).
  • Улучшена обработка вложенных плейсхолдеров — теперь они работают корректно в любых комбинациях.
  • Все известные проблемы (GSF) исправлены.

🚀 Как это работает (для совсем новичков)

  1. Скачиваете архив фреймворка
  2. Распаковываете в папку вашего сайта
  3. В site.js пишете свои настройки и собственные функции (по желанию)
  4. В HTML вставляете плейсхолдеры (по желанию) и страница сама наполняется данными
⚡ Важно: Фреймворк не требует сервера для работы. Вы можете открыть index.html прямо в браузере (через локальный сервер для корректной загрузки внешних данных, но сам HTML работает и без него). Теперь фреймворк запускается автоматически, даже если site.js пустой.

📁 Структура файлов

мой-сайт/
├── gradus-web.js        ← утилиты (кэш, кодирование, капча, SecretStorage, античит, Shop) — НЕ ТРОГАЙТЕ
├── database.js          ← локальная база данных (JSON + localStorage) — НЕ ТРОГАЙТЕ
├── server.js            ← запросы к API и Firebase (со встроенным CORS-прокси) — НЕ ТРОГАЙТЕ
├── client.js            ← движок плейсхолдеров {} — НЕ ТРОГАЙТЕ
├── core.js              ← сборка и автоинициализация фреймворка — НЕ ТРОГАЙТЕ
├── site.js              ← ВАШ КОД: настройки, свои функции (может быть пустым)
├── index.html           ← ВАША СТРАНИЦА (можно создавать сколько угодно)
└── db.json              ← ПРИМЕР начальных данных (можно удалить или изменить)
🛑 Никогда не изменяйте файлы: gradus-web.js, database.js, server.js, client.js, core.js. Они составляют ядро фреймворка. Все ваши дополнения и настройки должны быть только в site.js и ваших HTML-файлах.

📄 Назначение каждого файла

1. gradus-web.js (утилиты) — v2.5.1

Содержит глобальный объект GradusWeb с модулями:

  • cache — кэш с TTL и лимитом размера.
  • encode / decode — кастомное кодирование.
  • toBase64 / fromBase64 — Base64.
  • captcha — математическая капча.
  • ddos — защита от частых действий.
  • generate — генераторы (UUID, пароль, число).
  • notify — тосты-уведомления (ограничение до 3).
  • secretStorage — шифрованное хранилище (AES‑GCM, защита от перебора).
  • security — защита от F12, санитизация HTML (с сохранением тегов форматирования).
  • antiCheat — античит для переменных.
  • throttle — ограничение частоты вызовов с отменой.
  • shop (новое!) — корзина, каталог, промокоды, расчёт стоимости.

Вы можете использовать эти утилиты в своём коде напрямую: GradusWeb.cache.set(...), GradusWeb.shop.cart.add(...) и т.д. Но не редактируйте сам файл.

2. database.js (локальная БД)

Хранит данные в localStorage. При инициализации загружает начальные данные из db.json (если он указан и доступен). Если dbFile не задан или равен null/пустой строке, БД запустится пустой без ошибок.

3. server.js (запросы наружу) — v2.5.1

Объект GradusServer даёт методы для HTTP-запросов. Теперь со встроенным CORS-прокси, повторными попытками и кэшированием ответов! Если прямой запрос блокируется политикой CORS, библиотека автоматически перенаправит его через публичный прокси‑сервер.

  • get(url) — GET-запрос (с авто‑прокси, кэшированием на 1 мин и до 2 повторных попыток при сбое).
  • post(url, body) — POST-запрос с JSON-телом.
  • put(url, body) — PUT-запрос (точная замена).
  • firebaseGet(path) — обёртка для GET к Firebase REST API.
  • firebaseSet(path, data) — запись данных в Firebase через PUT.
  • firebasePush(path, data) — добавление данных со случайным ключом (POST).
  • setCorsProxy(url) — задать свой прокси (по умолчанию https://corsproxy.io/?url=).

Бесплатные CORS-прокси, которые можно использовать:

  • corsproxy.io – просто добавьте https://corsproxy.io/?url= к вашему URL.
  • AllOrigins – https://api.allorigins.win/raw?url=.
  • Собственный прокси на сервере – например, однострочный на Node.js или Cloudflare Worker.

4. client.js (парсер шаблонов) — v2.5.1

Это сердце фреймворка. После загрузки страницы он проходит по всем элементам и текстовым узлам, ищет конструкции вида {функция:аргументы} и заменяет их на результат выполнения функции. Поддерживает вложенные вызовы, автоматическую санитизацию (защита от XSS) и новые плейсхолдеры для Shop. Защищает от переопределения встроенных обработчиков.

5. core.js (инициализатор) — v2.5.1

Объект GradusStatic запускает фреймворк автоматически. Если вы не определили initSite в site.js, ничего страшного — фреймворк всё равно отработает.

⚙️ Файл site.js — ваша главная песочница

site.js — единственное место, куда вы пишете свой код. Он может быть пустым — фреймворк всё равно запустится и обработает плейсхолдеры. Если же вам нужны настройки или свои обработчики, используйте следующую структуру:

// (необязательно) Ваши настройки
const siteConfig = {
    debug: false,          // если true, защита от F12 отключается
    dbFile: '/db.json'     // путь к начальным данным (можно не указывать или оставить пустым)
};

// (необязательно) Функция инициализации
async function initSite() {
    // Создаём античит (пример)
    const ac = GradusWeb.antiCheat.createInstance((name, val, reason) => {
        console.warn('Взлом!', name, reason);
    });
    ac.startMonitoring();

    // Здесь можно регистрировать свои обработчики, писать в кэш, SecretStorage и т.д.
    GradusWeb.cache.set('username', 'Гость');
    await GradusWeb.secretStorage.set('api_key', 'sk_...');
    // ... ваш код ...
}

// Раньше требовался вызов: window.addEventListener('load', () => GradusStatic.init(siteConfig));
// Теперь фреймворк запускается автоматически, поэтому эта строка не нужна.
// Но если вы хотите передать свой конфиг, можно оставить (дублирования не будет).
GradusStatic.init(siteConfig); // Можно и без этого — автоинициализация подхватит.

👨‍💻 Создание своих функций

async function initSite() {
    GradusStatic.registerHandler('hello', (name) => `Привет, ${name}!`);

    GradusStatic.registerHandler('get_price', async (productId) => {
        const url = `https://api.example.com/price/${productId}`;
        const resp = await GradusServer.get(url);
        return resp;
    });
}

В HTML: {hello:{cache_read:username}}, {get_price:123}. Ошибки в ваших обработчиках теперь не ломают страницу — вместо этого выводится «ERROR».

🧠 Вложенные вызовы и несколько аргументов

{hello:{cache_read:username}}           ← сначала выполнится cache_read, потом hello

Несколько аргументов разделяются запятыми:

{concat:Hello, ,World!}               → "Hello World!"
{currency_rate:USD,RUB}              → вызовет функцию currency_rate("USD", "RUB")

📦 Использование database.js и db.json

По умолчанию при запуске фреймворк пытается загрузить /db.json. Вы можете изменить путь в настройках или оставить поле пустым — ошибки не будет.

{
  "site_title": "Мой блог",
  "theme": "light"
}

В HTML: {db_read:site_title}. Изменения сохранятся в localStorage.

🔒 SecretStorage и безопасность

Шифрованное хранение (AES‑GCM). Ключ теперь удаляется из памяти после использования. Защита от перебора блокирует хранилище на 30 секунд после 5 неудачных попыток расшифровки.

await GradusWeb.secretStorage.set('token', 'sk_abc123');
const token = await GradusWeb.secretStorage.get('token');

🛒 Интеграция с Shop (новое)

Магазин доступен через GradusWeb.shop. В HTML вы можете выводить информацию о товарах и корзине с помощью плейсхолдеров {product_*} и {cart_*}. Предварительно каталог нужно загрузить через site.js:

async function initSite() {
    await GradusWeb.shop.catalog.loadFromJSON('/products.json');
}

🚫 Ограничения и безопасность

  • Не храните секреты в открытом виде. Используйте SecretStorage или сервер.
  • Firebase: настройте правила доступа корректно, чтобы не слить данные.
  • Локальная БД: только для нечувствительных настроек.
  • Капча и DDoS-защита — клиентские, легко обходятся.

🏁 Быстрый старт с нуля

  1. Создайте папку проекта.
  2. Скачайте все 5 файлов ядра и положите в неё.
  3. Создайте index.html и (опционально) site.js.
  4. Запустите локальный сервер: python -m http.server 8000
  5. Откройте http://localhost:8000.

Минимальный index.html

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Мой сайт</title>
    <script src="gradus-web.js"></script>
    <script src="database.js"></script>
    <script src="server.js"></script>
</head>
<body>

    <script src="client.js"></script>
    <script src="core.js"></script>
    <script src="site.js"></script>  <!-- может быть пустым -->
</body>
</html>

🔄 Что можно менять, а что нельзя

  • ИЗМЕНЯЙТЕ СМЕЛО: site.js, index.html (и другие ваши HTML), db.json (или удалите его).
  • НЕ ТРОГАЙТЕ: gradus-web.js, database.js, server.js, client.js, core.js.

🧪 Проверка работы

Откройте консоль браузера (F12). Если debug: true, вы увидите сообщения [CORE]. В рабочем режиме ставьте debug: false.
