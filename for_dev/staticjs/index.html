📘 Gradus Static.JS — Полная документация

Gradus Static.JS — это микро‑фреймворк для создания динамических сайтов на статических хостингах (GitHub Pages, Netlify, обычный сервер без PHP/Python).
Он позволяет вставлять в HTML специальные метки {функция:аргументы}, которые при загрузке страницы заменяются на реальные данные: из кэша, локальной базы, API, генераторов и т.д.

Главная особенность: вам не нужно писать серверный код — всё работает прямо в браузере. Вы просто пишете обычный HTML и добавляете плейсхолдеры.

🚀 Как это работает (для совсем новичков)

  1. Скачиваете архив фреймворка
  2. Распаковываете в папку вашего сайта
  3. В site.js пишете свои настройки и собственные функции (по желанию)
  4. В HTML вставляете плейсхолдеры (по желанию) и страница сама наполняется данными
⚡ Важно: Фреймворк не требует сервера для работы. Вы можете открыть index.html прямо в браузере (через локальный сервер для корректной загрузки внешних данных, но сам HTML работает и без него).

📁 Структура файлов

мой-сайт/
├── gradus-web.js        ← утилиты (кэш, кодирование, капча и др.) — НЕ ТРОГАЙТЕ
├── database.js          ← локальная база данных (JSON + localStorage) — НЕ ТРОГАЙТЕ
├── server.js            ← запросы к API и Firebase — НЕ ТРОГАЙТЕ
├── client.js            ← движок плейсхолдеров {} — НЕ ТРОГАЙТЕ
├── core.js              ← сборка и запуск фреймворка — НЕ ТРОГАЙТЕ
├── site.js              ← ВАШ КОД: настройки, свои функции, инициализация
├── index.html           ← ВАША СТРАНИЦА (можно создавать сколько угодно)
└── db.json              ← ПРИМЕР начальных данных (можно удалить или изменить)
🛑 Никогда не изменяйте файлы: gradus-web.js, database.js, server.js, client.js, core.js. Они составляют ядро фреймворка. Все ваши дополнения и настройки должны быть только в site.js и ваших HTML-файлах. Это правило придумано, чтобы вы могли легко обновлять фреймворк, не теряя свои изменения.

📄 Назначение каждого файла

1. gradus-web.js (утилиты)

Содержит глобальный объект GradusWeb с модулями:

  • cache — хранение данных в localStorage с временем жизни (TTL).
  • encode / decode — кастомное кодирование строк по большой таблице символов.
  • captcha — математическая капча (генерация + проверка).
  • ddos — защита от слишком частых действий (rate limiter).
  • generate — генерация UUID, паролей, случайных чисел.
  • notify — красивые всплывающие уведомления на странице.

Вы можете использовать эти утилиты в своём коде (site.js) напрямую: GradusWeb.cache.set(...), GradusWeb.notify.success(...) и т.д. Но не редактируйте сам файл.

2. database.js (локальная БД)

Объект GradusDB позволяет хранить данные между сессиями пользователя. При инициализации он:

  1. Пытается загрузить начальные данные из файла /db.json (если файл существует и доступен).
  2. Затем применяет изменения, сохранённые в localStorage (более приоритетные).

Методы: get(key) — асинхронное чтение, set(key, value) — запись (сразу в localStorage), delete(key) — удаление. Данные хранятся в localStorage в открытом виде.

⚠️ Не храните в db.json или через GradusDB.set() пароли, токены Firebase, личные ключи! Эти данные доступны любому, кто откроет инструменты разработчика в браузере. db.json — только для общедоступных начальных настроек (например, текст приветствия, ID товаров). Для секретов используйте серверную часть.

3. server.js (запросы наружу)

Объект GradusServer даёт методы для HTTP-запросов:

  • get(url) — GET-запрос, возвращает текст ответа.
  • post(url, body) — POST-запрос с JSON-телом.
  • firebaseGet(path) — обёртка для GET к Firebase REST API (полный URL с .json).
  • firebaseSet(path, data) — запись данных в Firebase через PUT.

Используйте их в своих обработчиках для получения данных с любых публичных API.

4. client.js (парсер шаблонов)

Это сердце фреймворка. После загрузки страницы он проходит по всем элементам и текстовым узлам, ищет конструкции вида {функция:аргументы} и заменяет их на результат выполнения функции. Поддерживает вложенные вызовы!

5. core.js (инициализатор)

Объект GradusStatic запускает фреймворк: загружает БД, вызывает вашу функцию initSite() (если она объявлена в site.js), затем запускает рендеринг страницы.

⚙️ Файл site.js — ваша главная песочница

site.js — единственное место, куда вы пишете свой код. В нём можно:

  • Настроить конфигурацию (debug, путь к db.json).
  • Зарегистрировать собственные функции для плейсхолдеров.
  • Выполнить любую подготовительную логику (например, положить что-то в кэш).
  • Полностью удалить примеры — оставить только настройки и запуск.

Обязательная структура site.js:

// 1. Ваши настройки
const siteConfig = {
    debug: true,            // показывать логи в консоли
    dbFile: '/db.json'      // путь к файлу начальных данных (можно убрать, если не нужен)
};

// 2. (Необязательно) Функция инициализации
async function initSite() {
    // Здесь можно регистрировать свои обработчики, писать в кэш и т.д.
    GradusWeb.cache.set('username', 'Гость');
    // ... ваш код ...
}

// 3. Запуск фреймворка
window.addEventListener('load', () => {
    GradusStatic.init(siteConfig);
});

Если вы не определите initSite, ничего страшного — фреймворк просто запустит рендеринг без дополнительных действий. Вы можете вообще очистить site.js до такого состояния:

const siteConfig = {};
window.addEventListener('load', () => GradusStatic.init(siteConfig));

👨‍💻 Создание своих функций

Вы можете добавить любую логику, зарегистрировав обработчик в initSite(). Функция может быть синхронной или асинхронной, принимать несколько аргументов.

async function initSite() {
    // Регистрируем обработчик "hello"
    GradusStatic.registerHandler('hello', (name) => {
        return `Привет, ${name}!`;
    });

    // Более сложный: запрос к API
    GradusStatic.registerHandler('get_price', async (productId) => {
        const url = `https://api.example.com/price/${productId}`;
        const resp = await GradusServer.get(url);
        return resp;  // вернёт JSON как строку (можно распарсить)
    });
}

После регистрации используйте в HTML:

<p>{hello:{cache_read:username}}</p>
<p>Цена товара: {get_price:123}</p>

Важно: аргументы передаются через запятую, поэтому если вам нужна запятая внутри аргумента, сохраните значение в кэш/БД и используйте вложенный вызов: {myFunc:{cache_read:myKey}}.

🧠 Вложенные вызовы и несколько аргументов

Фреймворк умеет обрабатывать конструкции, где внутри аргумента находится другой вызов:

{hello:{cache_read:username}}           ← сначала выполнится cache_read, потом hello

Несколько аргументов разделяются запятыми:

{concat:Hello, ,World!}               → "Hello World!"
{currency_rate:USD,RUB}              → вызовет функцию currency_rate("USD", "RUB")

Если внутри аргумента нет двоеточия, он считается простой строкой. Если есть — рекурсивно обрабатывается.

📦 Использование database.js и db.json

По умолчанию при запуске фреймворк пытается загрузить /db.json. Вы можете изменить путь в настройках dbFile: '/data/initial.json' или убрать вовсе (dbFile: ''), если БД не нужна.

Пример db.json:

{
  "site_title": "Мой блог",
  "theme": "light",
  "items_per_page": 10
}

В HTML используйте {db_read:site_title}. Изменения, сделанные через {db_write:theme,dark} или GradusDB.set('theme', 'dark'), сохранятся в localStorage и переживут обновление страницы.

💡 Совет: если вы используете GitHub Pages, файл db.json будет загружен, но любые изменения на сервер не сохранятся — они останутся только у посетителя в браузере.

🚫 Ограничения и безопасность

  • Не храните секреты в коде и данных. Весь JavaScript выполняется на стороне клиента и может быть прочитан. Токены, ключи API, пароли должны быть на сервере.
  • Firebase: если используете Firebase, убедитесь, что правила доступа настроены правильно. Для публичных данных можно разрешить чтение всем.
  • Локальная БД: используйте только для нечувствительных настроек (тема, язык, никнейм). Не пишите туда email, настоящие имена и т.п. — они доступны в localStorage.
  • Математическая функция calc: выполняет выражение через Function(), но фильтрует всё, кроме цифр и знаков. Не передавайте туда пользовательский ввод.
  • Капча и DDoS-защита реализованы на клиенте и легко обходятся — они служат лишь для удобства, а не как серьёзная защита.

🏁 Быстрый старт с нуля

  1. Создайте папку проекта.
  2. Скачайте все 5 файлов ядра (gradus-web.js, database.js, server.js, client.js, core.js) и положите в неё.
  3. Создайте index.html с подключением скриптов (как в примере ниже).
  4. Создайте site.js с минимальной конфигурацией (см. выше).
  5. Откройте терминал в папке и запустите python -m http.server 8000 (если есть Python). Или используйте любой другой локальный сервер.
  6. Откройте браузер и перейдите на http://localhost:8000.

Минимальный index.html

<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Мой сайт</title>
    <script src="gradus-web.js"></script>
    <script src="database.js"></script>
    <script src="server.js"></script>
</head>
<body>
    <h1>{hello:{cache_read:username}}</h1>

    <script src="client.js"></script>
    <script src="core.js"></script>
    <script src="site.js"></script>
</body>
</html>

📚 Пример полного site.js с комментариями

// site.js — ваш файл управления

// 1. Конфигурация
const siteConfig = {
    debug: true,          // выводить в консоль информацию о работе
    dbFile: '/db.json'    // начальные данные (можно закомментировать)
};

// 2. Инициализация (вызывается автоматически перед рендерингом)
async function initSite() {
    // Можем сразу положить что-то в кэш
    GradusWeb.cache.set('username', 'Гость', 3600);   // хранить час
    GradusWeb.cache.set('greeting', 'Привет, Мир!'); // без TTL будет 3600 сек по умолчанию

    // Регистрируем кастомную функцию для получения курса валют
    GradusStatic.registerHandler('currency_rate', async (from, to) => {
        try {
            const url = `https://api.exchangerate-api.com/v4/latest/${from}`;
            const resp = await GradusServer.get(url);
            const data = JSON.parse(resp);
            if (data && data.rates && data.rates[to]) {
                return data.rates[to].toFixed(2);
            }
            return '—';
        } catch (e) {
            return '—';
        }
    });

    // Простая функция приветствия
    GradusStatic.registerHandler('hello', (name) => `Привет, ${name}!`);
}

// 3. Запускаем фреймворк при полной загрузке страницы
window.addEventListener('load', () => {
    GradusStatic.init(siteConfig);
});

🔄 Что можно менять, а что нельзя

  • ИЗМЕНЯЙТЕ СМЕЛО: site.js, index.html (и другие ваши HTML), db.json (или удалите его, если не нужен).
  • НЕ ТРОГАЙТЕ: gradus-web.js, database.js, server.js, client.js, core.js. Эти файлы — ядро, их обновления могут выходить отдельно, и ваши правки будут потеряны.

Если вам нужно расширить функциональность, пишите код в site.js и используйте GradusStatic.registerHandler.

🧪 Проверка работы

Откройте консоль браузера (F12). Если debug: true, вы увидите сообщения [CORE], [DB] и т.д. Ошибки в плейсхолдерах также будут видны. В рабочем режиме ставьте debug: false.
